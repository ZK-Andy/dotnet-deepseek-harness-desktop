# 会话收尾检查单（session-close）

> 每个开发批次完成或会话结束时执行（长会话可多轮触发，由 feature-flow 步骤 8 调用）；全部完成才算收尾（教训：共享 home 三条提交未记录，导致下个会话误读决策；README 徽章曾漂移到 25/25 而实测 300+，数月无人察觉——收尾清单没有它就没有更新者）。

1. **提交对账**：`git log` 本会话全部提交 vs HANDOFF 最新记录——每条提交必须能对应到交接条目。
2. **决策落档（结论只落 durable 四家）**：本轮拍板结论是否已进 ADR / `docs/cookbook.md` / README / AGENTS？没有则补。**结论只落 durable 四家，不落 HANDOFF 滚动窗**——滚动窗不复述结论（见 docs-management-tiering）；凡待跨会话用的复现细节/取证点/判据，正文进 durable 家，滚动窗与待办区只留指针。
3. **待办对账（跨会话遗留的唯一落点）**：HANDOFF **待办区（`HANDOFF-todos.md`）**增删——本轮产生的跨会话遗留/观察/待复现项（够不上「结论/决策」的那类，如围捕待复现、待上游回应）**必须写进待办区**（写清受影响面与前置研究点；`[ ]` 条 ≤340 字、`[x]` 压缩为一行指针），不留滚动窗副本；新立事项同此。
4. **README 双语同步（强制，每次收尾必做）**：核对 `README.md` / `README.en.md` 与 shipped 现实——测试徽章与实测基线、覆盖率、功能清单、目录与计数、版本相关表述（vX.Y.Z 与资产形态）；**有漂移即双语同步修正并随本批次提交**；无漂移也无法偷懒——在收尾汇报中显式说明「README 核对无变更」。README 是产品门面，只有收尾清单强制它才会有人更新它。
5. **未推送提醒**：本地领先 origin 的提交数如实告知用户；是否推送由用户定或按既定惯例。
6. **工作树确认**：`git status` 干净；untracked 仅限预期清单（HANDOFF.md、`.plan/`、`.cache/` 等）。
7. **交接条目**：HANDOFF「交接更新记录」滚动窗追加本会话**精条目**——日期｜类型｜**指向 ADR（`.agents/notes/<…>` 一行主题，不复述结论）**｜关键提交哈希（对账锚点，保留）｜README 同步结论一行（无变更／有漂移已同步）。**前置判据（fail-loud）**：凡本轮拍板的结论必须已在步骤 2 落 durable 家；**未落则先补 ADR，不得以收紧条目代替**。跨会话遗留/复验观察一律经步骤 3 入待办区，滚动窗不留副本。
8. **收尾汇报**：向用户汇报时附「待办全景速览」——按 A 待拍板 / B 实机复验 / C 随手候选 / D 远期 四分类列当前待办（**此为速览视角、非穷尽法规——完整待办以 HANDOFF 待办区为准**；流程性-待生效项可归「其他/挂账」类）；README 核对结论（变更或「无变更」）一并说明。
