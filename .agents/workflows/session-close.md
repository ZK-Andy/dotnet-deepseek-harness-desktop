# 会话收尾检查单（session-close）

> 每个开发批次完成或会话结束时执行（长会话可多轮触发，由 feature-flow 步骤 8 调用）；全部完成才算收尾（教训：共享 home 三条提交未记录，导致下个会话误读决策）。

1. **提交对账**：`git log` 本会话全部提交 vs HANDOFF 最新记录——每条提交必须能对应到交接条目。
2. **决策落档**：本轮讨论的拍板结论是否已进 ADR / HANDOFF？没有则补。
3. **待办对账**：HANDOFF 待办区增删（新立事项写清受影响面与前置研究点）。
4. **未推送提醒**：本地领先 origin 的提交数如实告知用户；是否推送由用户定或按既定惯例。
5. **工作树确认**：`git status` 干净；untracked 仅限预期清单（HANDOFF.md、`.plan/`、`.cache/` 等）。
6. **交接条目**：HANDOFF 顶部追加本会话记录——日期｜类型｜一句话结论｜关键提交哈希｜遗留事项。
7. **收尾汇报**：向用户汇报时附「待办全景速览」——按 A 待拍板 / B 实机复验 / C 随手候选 / D 远期 四分类列当前待办。
