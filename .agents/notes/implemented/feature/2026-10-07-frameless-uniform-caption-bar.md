## Problem

壳窗口默认是平台原生标题栏，与官方 DeepSeek 桌面端的无边框观感割裂：标题条占纵向空间、观感随平台各自为政。需求方要求三端统一官方 **macOS** 截图呈现的形态：内容满幅到顶、无独立标题带、红绿灯悬浮在侧栏顶区（且折叠按钮与红绿灯同行）。Ryn 0.38.0 内建 chrome 控制面（`TitleBarStyle`、自动拖拽条、`data-webview-*` 声明式窗口控制），具备零自研底座的条件。

## Decision

**三端统一 `TitleBarStyle.Frameless` + 壳自绘 macOS 观感**：窗口是我们的，量自己的 chrome、画自己的按钮——**不向 dsh 客户端冒充任何宿主身份**。

- **窗口**：`Frameless`（去原生 chrome，含 macOS 红绿灯）+ `TitleBarAutoDragHeight = CaptionBarOptions.HeightPx`（默认 52 = 官方 macOS 侧栏顶条；webview 不认 `-webkit-app-region`，Ryn 的 mousedown 拖拽条是等价物，双击缩放内建）。
- **注入脚本**（`PageBridge.CaptionBar.Build`，幂等可重挂；除 macOS 两项差异外三端同款）：
  1. 把宿主 chrome 高度登进 dsh 的公开变量：`--dsh-frame-top-clearance` 随高度发布（客户端 JS 无条件读取以让布局/浮层定位避开）；`--dsh-frame-chrome-top` 恒为 `0px`，使模态遮罩画满全视口——上游该变量只为窗外原生 caption 留空（`AppFrame.module.css` 仅 Windows 分支发布、全屏归零，macOS darwin 分支不发布），本壳顶带是窗内页面（含 dsh 自己的 tab 条），随高度发布会把顶带排除在遮罩绘制之外（设置弹窗顶栏不暗）。这是宿主本职，不是冒充。
  2. **侧栏列顶部让位** `padding-top`：padding 属元素自身背景盒，让位带被侧栏自身填充色无缝覆盖 → 无色带、无色差（`[class*="sidebarCol"]` 后缀选择器 + `:where(:has(> [data-shell-bottom]):has(> :nth-child(2)) > :first-child)` 结构式双兜底；侧栏列无稳定 data-* 钩子，真实 DOM 实测 frame > `.<hash>_sidebarCol`。兜底式以 `:where()` 归零权重并要求父级另有第二子——侧栏列挪位时最坏只是不再命中，不会把让位间距误打到内容列首元素上）。
  3. **折叠按钮回到让位带右端**（官方 darwin 布局把它放顶条里、与红绿灯同行）：`transform` 上移（不改布局盒，x 与侧栏宽度无关）+ 同批放开品牌行 `overflow` 裁剪（不放开则几何到位却画不出来）、不新增自绘按钮（会与原生重复）；折叠态把裁剪与位移一并还原，按钮留在轨内可点。
  4. **红绿灯三点**：12px 系统色圆点（`#ff5f57/#febc2e/#28c840`），位置对齐官方 `trafficLightPosition(16,18)`，悬停出深色符号；点击走 Ryn 对 `data-webview-close/minimize/maximize` 的委托监听（`window.*` IPC，能力面 = ryn.json `window` 节细粒度 allow-list，`RynWindowCapabilityTests` 钉集相等）。**绿灯在闸内另走原生全屏**（官方 macOS 绿灯是 Enter Full Screen，窗口缩放另有其键）：属性换成本壳自有 `data-dsh-fullscreen` + 自绑点击调 `window.setFullscreen`，可达名随之改（`UiCopy.CaptionFullscreenName`）；Ryn 0.38 无 fullscreen 查询命令，故不存标志位而用无状态几何判据（`|innerHeight-screen.height|≤2 且 |innerWidth-screen.width|≤2` ⇒ 判为已全屏；全屏铺满整屏且菜单栏自动隐藏，窗口缩放只占工作区、高度差 &gt; 2），每次点击现算，导航与外部退出都不会让状态漂移。闸外（含非 macOS 与 Rosetta-x64）绿灯仍是窗口缩放。
  5. **注入条保持可命中**（不设 `pointer-events:none`）：三个圆点的点击落点在这条自绘条上，透明化即失去三键。**顶带拖拽面不由本条决定**——Ryn 自动拖拽条对「盖住条带却向下延伸」的命中元素一律按内容处理（`docs/custom-title-bars.md`），而侧栏列与会话头部正是这类自顶带起算的 chrome，故判定已收归本壳（见下条），本条只是碰巧落在带内的一个命中体（条内非按钮区域也算壳带，见下条判据）；它盖住的正是自家 padding 造出的空白侧栏区（区无 dsh 控件），吞事件在此不损失可达性。
- **原生 chrome 的平台闸（判据单点 `PageBridge.MacNativeChrome`，`IsEnabled` = macOS 且非 Rosetta-x64；纯函数 `ShouldEnable(isMacOs, process, os)` 供真值表回归钉）**：窗口侧 `RynOptions.Backdrop` 与注入侧的 `macChrome` 同源此判据。**排除 Rosetta-x64 的根据**：release run `37545883056` 同一份代码 mac arm64 腿绿、mac x64 腿 `Segmentation fault: 11`（该腿上次绿是 v0.6.2，本批唯一的原生层改动就是 backdrop）。【推断 · 未证】机理——Ryn 的原生窗口路径按 `OSArchitecture` 挑结构体返回 ABI（`objc_msgSend_stret` 与 arm64 变体各一支），Rosetta 下该属性报 Arm64（.NET 7+ 语义）→ 取错分支 → ABI 失配；同族前科：`TitleBarStyle.Overlay` 的原生红绿灯在 mac x64 同样 segfault（run `37532237576`，见 Alternatives 的 Overlay 条）。**真实 Intel Mac（X64/X64）不在排除面内、仍走原生路径**——该面本机无真机、也无 CI 腿（x64 腿跑在 arm64 runner 上即 Rosetta），故列入 macOS 真机验收项。降级形态是**整条原生增强一起退出**（绿灯回落窗口缩放、不设 backdrop）：保守取舍——两者共同依赖「本进程能安全用原生窗口 API」这一尚未逐项取证的前提，分裂会留下半开状态。
- **macOS 毛玻璃**（官方 vibrancy 观感，`MacNativeChrome.IsEnabled` 分支）：窗口侧 `RynOptions.Backdrop = Blur`（Ryn 会把窗/网页背景清成透明，再由 `NSVisualEffectView` 垫材质；闸外恒 None，否则只剩透明窗露底）；页面侧由注入脚本补官方那条**透明链**（`html,body` 透明 + 侧栏列改 80% 不透明的 `color-mix` 色调，材质经此透出）。官方侧栏色标取 `--dsw-specific-sidebar-fill` 的渐变叠色，且整链以 `html[data-platform='darwin']` 门控，而该属性正是本壳禁用的宿主冒充开关（见 Alternatives）；故改为注入期按平台取舍、色标改用通用 `--dsw-alias-bg-base` 的 80% 不透明 `color-mix` 近似（**已知偏离**：与 dsh 自带 darwin 规则的取色/减透明回退不同，观感以真机为准）。
- **能力面**：`window.setFullscreen` 进 ryn.json allow-list，`RynWindowCapabilityTests` 的「恰好集」随之扩到七项（Ryn 注入脚本六命令 + 本壳绿灯命令）。Ryn 的能力面文件无平台条件字段，故该命令在 Windows/Linux 同样被放行（**已知扩大**：那两端无消费点，仅闸内分支调用；宁可显式登记也不引入平台分裂的能力文件）。
- **注入时机（三路互补）**：① **引擎侧注册**——`IRynWebView.InjectScriptAsync` 把同一份脚本注册为「每次页面加载执行」（Ryn 契约原文 "runs on every page load"；saucer 层 macOS 走 `WKUserScriptInjectionTimeAtDocumentEnd`、Windows 在 `DOMContentLoaded` 逐导航重放 `run_at == ready` 的脚本、Linux 走 `webkit_user_script_new(…, DOCUMENT_END, …)` + 用户内容管理器脚本）。三路里它是**唯一能在不依赖导航事件的前提下覆盖后续每次文档加载**的一路：holder 页 `location.reload()` 进真 UI 是**同 URL 重载**，而 `navigated` 回调在 mac/win 挂在 saucer 的 `URL`/`Source` 变化上（Linux 挂在 `WEBKIT_LOAD_COMMITTED`，每跳都发——故 Linux 上 ①③ 都覆盖同 URL 重载，mac/win 上只有 ① 覆盖）——真 UI 文档因此在 mac/win 拿不到顶栏（v0.5.21–v0.6.3 四轮发版冒烟腿与本机 host.log 的 `[nav] 导航已到达` 观测计数：Linux 2 条、mac/win 1 条；四轮一致，非单 run 复现）。注册按 `no_frames=0` 注入**所有 frame**（interop 声明 `saucer_webview_inject(webview, code, run_at, no_frames, clearable)`；Ryn 传 `run_at=READY, no_frames=0, clearable=1`，第 4 位 `no_frames=0` ⇒ 非主框架限定），故脚本自带顶层文档守卫。② **接线即注入**当前文档一次（注册只对**后续**文档生效，当窗空档由它兜）；③ **常驻导航钩子** `RynNavigationCallbacks.SetOnNavigatedPersistent` 每次到达后重挂（Linux 每跳都发；三路共用同一份脚本——语言由执行期按 `html[lang]` 现取，构建期 locale 只是该属性缺失时的回落，故无需按到达重建）。三路都幂等（脚本自带元素/样式双守卫），脚本挂监督器取消令牌；失败仅留痕（托盘菜单是窗口控制退路）。可达名双语都进脚本、执行期按 `html[lang]` 现取（dsh 侧语言单一来源；该属性缺失时回落宿主当时 locale），故注册脚本不必随语言切换重注册。注册的预算按**到点**表达（`RuntimeTimeouts.CaptionBarRegisterSeconds`，默认 60s，节拍沿用 `PushRetryDelayMilliseconds`，由 `PagePump.AttemptsForBudget` 单点折算成尝试次数、不读墙钟）：mac x64（Rosetta）的 webview 创建晚于按次数计的 6s 预算（v0.6.4 发版腿 `37602761492` 该腿 host.log 为注册重试耗尽、2s 后才 `[nav] 导航已到达`、截图三色 0 px，而 arm64/Windows 同 run 已出三点），原次数口径表达不出「等到点/到取消」。常驻导航钩子另有**首次到达补注册**（一次性闩，`StartupSequence._captionBarReregistered`）：该事件只在 webview 就绪后发，是到点预算之外再保的一路注册时机——只补一次，避免每次导航都新增一条引擎注册；与到点路可能双发，脚本元素/样式双守卫使其无副作用（同三路叠加的既有形态）。四路就绪前重试共用单点循环（[pagepump-retry-helper-unification](../simplification/2026-10-07-pagepump-retry-helper-unification.md)）。
- **顶带拖拽判定收归本壳**（`CaptionBar.BuildDragBinding`）：Ryn 的自动拖拽条判据要求命中元素的 `getBoundingClientRect().bottom ≤ strip × 1.5`（默认 52 × 1.5 = 78），而 dsh 把整条顶带留给**自顶带起算的流内 chrome**——侧栏列的 padding 区（`frame` 实测 fixed，条内非按钮区域仍算壳带）→ `preventDefault()` 后 `window.startDrag`（mac 走 `window.beginNativeDrag`）。**判据量盒顶而非盒高**：按「盒高 ≥ 0.9 视口」判全高容器会漏掉会话头部这类条状 chrome，中间内容列因此整条不动（见 Alternatives）。两条判据的交集是「盒顶在带内且底边 ≤ mousedown 起的原生窗口移动由合成器隐式抓取承接，随后的 click/dblclick 序列不再到达页面【推断 · 未证：机制面在合成器，本机只能观察到「拖拽管用、双击不缩放」的实机现象，无事件级取证】——等 DOM 的 `dblclick`（或 Ryn 的同款委托）等于顶带永不缩放，故双击按**两次带内左键按下的间隔/位移**自判（`DoubleClickMs` = 500ms = 各平台双击窗上界（Windows/macOS 默认；GTK 默认 400ms）；`DoubleClickSlopPx` = 4px）→ `window.toggleMaximize`；该路**不置** `bandClaim`。DOM 的 `dblclick` 监听保留为**仲裁闸门下的兜底**（`if(!bandClaim||!bandPoint(e))return;`），但**不承担覆盖自判窗以外区间的职责**：顶带上该事件按上述前提不可达，自判窗取平台上界即全部覆盖。能力面不变（`startDrag`/`beginNativeDrag`/`toggleMaximize` 已在 ryn.json 的 `window` 细粒度 allow-list 内）。**最大化窗不做「先还原再拖」**：GTK 的 `gdk_wayland_toplevel_begin_move` 无最大化守卫（只发 `xdg_toplevel.move` + 隐式抓取 serial），mutter 照常起抓取并按 shake-loose 语义处置（依据见 Alternatives）。
- **占位页** `wwwroot/index.html` 内置同 id 同规格点簇（壳自有引导页无 dsh 侧栏，自带 52px 让位）。

### 官方 macOS 折叠侧栏后红绿灯的行为（源码对照，本节为参照系）

上游 `apps/desktop` 与 `packages/client/ui-layout/src/client/AppFrame.module.css`：折叠时**红绿灯完全不动**（AppKit 原生按钮，恒在 (16,18)、占位到 x=68）；侧栏列**整个隐藏**（darwin 下 `collapsedWidth = 0`，**无窄轨**——56px 窄轨是非 darwin 平台的行为）；折叠期挂载 `shell.leading` 座位（`top: 11px; left: 88px`，两个 28px 控件：展开侧栏 + 新会话，中线 y≈24 与红绿灯齐平），并发布 `--dsh-frame-leading-clearance: 160px`（红绿灯到 68 + 控件 88..152 + 8px 空隙）供顶到左上角的主面板让位；全屏时 macOS 隐灯，座位左移 `left:12px`、让位降到 84px。

本壳的偏离点：我们没认领 darwin（认领即冒充宿主、插件崩），折叠后拿到的是 dsh 的非 darwin 窄轨，三点（16..68）会跨到内容区上——故折叠态把三点收进轨内（内缩 10 + 3×10 + 2×6 = 52 ≤ 轨宽），不做「整列隐藏 + 座位重开控件」的完整复刻（那需要 darwin 布局）。

## Alternatives considered

- **注入 `data-platform='darwin'` 借用 dsh 内建 macOS 呈现（v0.6.1/0.6.2 实现，实测崩溃后废弃）**：该属性不是样式开关，而是 dsh 客户端的**桌面运行时开关**——`detectEnvironment` 见之即判 `runtime="desktop"`（官方 Electron 宿主语义），`dsh-client-shortcuts` 随即要求 `window.dshDesktop.keyboard`（官方 preload 桥，非 Electron 宿主不存在）并 `throw`，级联 25 个 UI 插件 pending，启动即显示「插件加载失败」屏。**实证**：v0.6.1 release 与 v0.6.2 首发安装后各一次；代码级根因见 `dsh-client-shortcuts/lib/client.js` 的 `detectEnvironment` 与 `ShortcutsService` 构造。冒充宿主身份的方案从此禁止。
- **注入 `data-windows-titlebar`（落败）**：纯 CSS 开关、不触发运行时误判，但那是 dsh 的 Windows 呈现（顶带 + 内容圆角卡片），非需求方指定的 macOS 形态。
- **注入 `window.dshDesktop` 假桥后继续用 `data-platform`（落败）**：桥面实测很小（`keyboard.closeWindow/subscribe` + `shortcuts` + `deviceInfo`），能骗过插件构造；但 `runtime="desktop"` 会把这些插件的**可配置快捷键判给「原生菜单」**（`installKeyboard(..., native=true)` 时 DOM 只喂固定动作），而本壳没有原生菜单——快捷键会静默失效。骗得过去 ≠ 不付代价。
- **`TitleBarStyle.Overlay` + `TrafficLightPosition` 原生红绿灯（v0.6.1 实现，实测崩溃后废弃）**：mac x64（Rosetta，macOS 26 runner）窗口创建后约 1 秒 `Segmentation fault: 11`（同批 arm64 全绿）；Ryn 0.38.0 该路径在 Rosetta 下不可用。上游修复后如需原生灯（悬停符号、全屏联动）可按平台回归，须先过 mac x64 冒烟腿。
- **`TitleBarStyle.Hidden`（落败）**：留空原生条，与满幅目标相反。
- **整条自绘 caption 色带（v0.6.0 实现，实机对照后废弃）**：自绘带用独立底色，与 dsh 页面拼接处必然出现色差线（需求方实机否决），且 macOS 上形态不符——正解是让让位带由侧栏自身填充覆盖（本轮）。
- **`window: true` 整前缀放行能力（落败）**：dsh 页面是上游不可控内容，`setSize/setPosition/setFullscreen` 等命令面无必要暴露。
- **宿主探针轮询「确保注入」（落败）**：逐拍 `EvaluateJavaScriptAsync` 探顶栏存在性、缺位才重跑注入脚本，配「快发窗 + 低频心跳」。需要新配置项与常驻 IPC 开销，且把「窗口何时换文档」变成靠节奏猜的时序。Ryn 0.38 已把「每次页面加载执行」做成注册式能力（`InjectScriptAsync`），覆盖同一场景且零轮询、零新参数——改用注册。
- **最大化窗「先还原再拖」（落败）**：原诊断据 GTK 源码推断 `xdg_toplevel.move` 对最大化 surface 是 no-op，故拟先 `toggleMaximize` 还原。源码对照不成立：`gdktoplevel-wayland.c` 的 `gdk_wayland_toplevel_begin_move` 除「surface 已销毁 / 未 realize」外无守卫，只发请求 + 隐式抓取 serial；mutter `meta-wayland-xdg-shell.c` 的 `xdg_toplevel_move` → `meta_window_begin_grab_op` → `meta-window-drag.c` 对最大化窗按「原 monitor 直移 / 拖动过竖直阈值才 shake-loose 还原」处置，并非 no-op。壳先替它还原反而与原生标题栏行为相左，还多一次几何跳变。
- **全宽透明拖拽带（`data-webview-drag`）覆盖顶带（落败）**：覆盖层会盖住带内的 dsh 控件（折叠态下侧栏折叠按钮正落在带内），而 Ryn 的交互排除按**命中元素**判定——命中元素变成覆盖层后 `closest('button')` 失效，按钮点击被吞；给覆盖层 `pointer-events:none` 则它自己不可命中。故只能由自持判据承担（不改布局、不加元素）。
- **按「盒高 ≥ 0.9 视口高」认流内全高容器（v0.6.4 实现，实机回归后收窄）**：该判据只认布局列，而 dsh 顶带的另一半 chrome 是**条状**的——内容列顶 52px 全落在会话头部里（`@deepseek-ai/dsh-client-ui-conversation@0.2.1-alpha.1` 的 `lib/client.js`：`.wSkVaW_header{box-sizing:border-box;min-height:76px;padding:10px 28px 0 20px;flex:none;display:grid}`，其 `root` 为 `flex-direction:column;height:100%` 的内容列首子——仓内 `artifacts/` 的 rc.7 副本尚无这条 `min-height`），命中元素永远不是全高容器，中间内容列因此拖不动也缩放不了。改用「盒顶在带内起算」后两类 chrome 同判据覆盖，且比按盒高判更严：带下内容（消息气泡、页面正文）盒顶 > 带高，天然让行。
- **`--dsh-frame-chrome-top` 随顶带高度发布（本批前形态，已订正为恒 `0px`）**：意图是让 dsh 浮层避开宿主 chrome，但上游该变量的语义是「窗外原生 caption 留空」（`Modal.module.css` 的 `.mask{inset:var(--dsh-frame-chrome-top,0px) 0 0}` 只避绘制、不避点击；`AppFrame` 仅 Windows 原生 caption 分支发布），本壳顶带是窗内页面——随高度发布后设置弹窗与通用模态的遮罩绘制从 52px 下开始，顶栏 tab 条不暗（看似可交互、实际点击已被拦）。订正后遮罩画满，红绿灯条（`z-index` 最大值）仍浮于遮罩之上可点，与原生模态行为一致。
- **等 DOM 的 `dblclick`（含 Ryn 的同款委托）承担顶带缩放（落败）**：本壳 mousedown 起的原生窗口移动由合成器隐式抓取承接，随后的 click/dblclick 序列不再到达页面【推断 · 未证：机制面在合成器，本机只有「拖拽管用、双击缩放不管用」的实机现象】。缩放只能与起拖同点自判（第二次带内按下），DOM 的 `dblclick` 降为 claim 闸门下的兜底（且不承担覆盖自判窗以外区间的职责）。
- **用 DOM 的 `e.detail===2` 替换双击自判状态机（未采）**：`mousedown` 的 `detail` 即点击计数、双击窗与位移由浏览器按平台设置判定，形态比自钉常量+状态机更简；但它与「序列被吞」同一未证前提绑定（detail 在 mouseup/click 缺失时是否仍递增未证），替换等于把修复押在待验假设上。真机复验若证其可靠，可用它替换 `DoubleClickMs`/`DoubleClickSlopPx` 与 `lastDown` 记账。

## Consequences

- 买到的：三端一致的官方 macOS 观感（满幅、无缝让位带、红绿灯与折叠按钮同行）；不冒充宿主身份，dsh 客户端插件行为与浏览器渲染一致（全部正常激活，快捷键仍由网页侧派发）。
- 付出的：让位与折叠按钮定位依赖 dsh 侧栏的类名后缀（`sidebarCol`/`toggle`/`collapsed`）与内部行内边距（上移量的 `+10px` 余量），dsh 大改侧栏结构时需随之校准——失效形态是「按钮/内容位置偏移」而非崩溃；`--dsh-frame-top-clearance` 是 dsh 客户端**读**的公开量，上游若改名同样只需校准（`--dsh-frame-chrome-top` 本壳恒发 `0px`，与上游回落一致）。
- 与官方 macOS 观感的已知差异：折叠时官方完全隐藏侧栏（把重开控件挂进 frame 的 leading 座位），本壳折叠仍走 dsh 的窄轨布局（轨道内容随让位整体下移到红绿灯之下）；macOS 全屏隐灯（官方 `html[data-fullscreen]` 让位/隐灯）未做——闸内绿灯已切原生全屏，但全屏态下本壳自绘灯仍随注入条留在于顶区。
- macOS 面（原生全屏切换、毛玻璃）的证据状态：**闸内那侧只有 mac arm64 腿验到「不崩」**（run `37545883056` arm64 腿绿），观感需真机；闸外降级那侧（Rosetta-x64）是**同一次 run 的 x64 腿崩溃**给出的落闸依据，其「加闸后不崩」待下一次发版腿复证。真实 Intel Mac 的原生路径既无 CI 腿也无真机 —— 列入 macOS 真机验收项。能启动应用的 mac 腿只在 `package.yml` 里跑，触发面是发布（`release.yml` 经 `workflow_call`，即 tag）与手动 `workflow_dispatch`；PR 期的 `ci.yml` mac 腿只跑两个过滤测试类、不启应用。
- 注册式注入买到的：同 URL 重载（holder 页自 reload、dsh 客户端自身 `location.reload()`）与任何换文档路径都不再依赖导航事件；代价是**执行时序交给引擎**（文档就绪时执行，注入条只是幂等再入场，双路叠加不重复建条），且注册脚本的语言分支只能从文档取——`html[lang]` 缺失时回落宿主 locale（可达名，不影响可见形态）。注册预算到点化后，慢启动平台（mac x64/Rosetta 实测）不再在 6s 处放弃；「退出期已销毁即放弃」随重试单点化对全部注入路生效（此前只有注册路有该语义），横幅与顶栏注入另补耗尽留痕（见该 ADR）。
- 拖拽判据的依赖与失效形态：依赖 dsh 顶带 chrome 仍「自顶带起算、且在流内」（实测 `frame`/`sidebarCol`/`centerCol`/`wSkVaW_header` 均 `position:relative` 且在流内，全客户端仅 4 处 `absolute`——leading 座位、列宽手柄、Windows 标题带伪元素、本壳自绘条）。上游若把顶带 chrome 改成定位元素或下移到带外，本判据自动让位（不接管、回到「拖不动」），**不会**变成吞掉页面交互；已知交集面是条状元素（盒顶在带内且底边 ≤ `strip×1.5`），由 `mousedown` 的 `defaultPrevented` 与 `dblclick` 的 `bandClaim` 两处仲裁闭合——claim 为假时本壳不再接双击，故不会双派发。双击自判的取舍：自判窗取各平台双击窗**上界**（500ms）而非 GTK 的 400ms 默认——顶带上 DOM `dblclick` 不可达，兜底路不承担覆盖职责，窄一档就会让 400–500ms 的慢双击退化成两次起拖；宽出的唯一效果是两次快速独立按下被当作双击，正是原生标题栏语义。
