# Agent Note: 工具调用纪律入 AGENTS.md（探索命令合并为单次调用）

Status: implemented

中文（双语暂不启用；启用时恢复 .md + .zh.md 配对 + .i18n.yaml）

## Problem

每次工具调用及其返回都永久留在会话上下文里，连同调用前后的中间判断。同一条信息用多次单目的探测取回，比一次复合调用贵——框架开销与中间推理被重复支付，占用随碎片数增长。

现象侧记录【探索性 · n=1 会话】：同仓库、同任务类、同一批数据源，唯一变量是驾驶位上的模型。前两轮各出复合命令（两轮共 7 次调用）；其后六轮共 21 次调用，其中一轮把一个插件的工具注册面拆成 9 次串行探测——同一份目录缓存被打开三次，因为每次只猜一层结构，末尾四次未取到目标常量。单会话样本不足以支撑跨模型结论【推断 · 未证】；它支撑的是「形态问题存在且可复现」。

规则缺口：既有「多个独立查询合并到同一次 bash 并行执行」住 [github-research](../../../workflows/github-research.md) 第 6 步，标题限定 GitHub 调研、条件限定「输出超约 50 行」，本机文件排查、插件检查、日志定位不在射程内；流程卡按需读取、不进会话开场注入，「该读没读」即失效点（本次复现的正是这一条）。

## Decision

根 [AGENTS.md](../../../../AGENTS.md) 新增 `## 工具调用纪律（强制）`，与 `## GitHub 调研纪律（强制）`、`## 检索通道路由（强制）` 同级，作常住纪律：

- 探索性命令合并为单次复合调用；结构未知时最多两跳（一次 dump 结构、一次按结构取数）。
- 禁止「猜一层、看一层」的串行探测，并写明代价机制：占用随碎片数增长。
- 适用面为本机文件排查、插件检查、日志定位等一切探索，不限于 GitHub 调研。

配套：`.agents/workflows/github-research.md` 第 6 步退化成本纪律在 gh 场景的应用（保留 `head` 截断与并行示例），指回 AGENTS.md——规则只住一处。

边界：本纪律**不可机器化**。门禁的输入面是工作树与提交，工具调用形态发生在会话运行时。它因而不进「评审检查项（AI 兜底）」（该清单只减不增），也不新增清单条目；违反按工具使用缺陷处理。

## Alternatives considered

- **放进 session-open 流程卡**：落败——流程卡不被注入，只在被读取时生效；本次失效的正是「该读没读」，把纪律再放一处需要主动读的地方不改变默认行为。
- **只放宽 github-research.md 第 6 步的标题与条件**：落败——按需读取的问题不变；且该卡主题是 GitHub 调研，通用工具纪律塞进专题卡会让标题与内容不符，按题检索不会命中。
- **做成门禁（统计每轮工具调用数并拦截）**：落败——仓库侧门禁读工作树与提交，看不到会话运行时的调用；在仓库里加只能靠人填的「自查项」是伪门禁。真硬约束在宿主/产品面。
- **写进「评审检查项（AI 兜底）」**：落败——该节明文只减不增，且工具调用形态不体现于 diff，评审代理在 diff 上无从核对。
- **只写 ADR 不改 AGENTS.md**：落败——ADR 是 rationale 的家，不是注入面；默认生效依赖被注入。

## Consequences

- 收益：探索动作的默认形态写进每个会话都会读到的文件，跨模型生效，不依赖某一模型的自律。
- 代价：AGENTS.md 是**被动注入**——能掰正默认行为，不能保证；无机械拦截。
- 字数：AGENTS.md 611 → 646（预算 800；判据唯一家 `scripts/doc-budgets.manifest.json`）。
- 单一事实源：gh 场景的截断与并行细则仍住 workflow 卡，规则住 AGENTS.md。
