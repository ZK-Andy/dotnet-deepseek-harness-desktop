# Agent Note: review-scope-narrowing（三重审核按 diff 面收窄——触发枚举化 + 面收窄量化 + 轻审前置机器化）

Status: implemented

Review: FULL/2026-09-03/R1=ok R2=ok R3=ok

中文（双语暂不启用；启用时恢复 .md + .zh.md 配对 + .i18n.yaml）

## Problem

`feature-flow.md` 步骤 5（三重审核执行契约）当前**触发面宽、执行面全量、缺量化**，导致"窄范围修改"也背"全仓语义审"的成本，耗时与修改范围不成正比：

1. **触发条件写得宽**：凡"改行为/安全面 / IPC 帧契约 / 发版链路 / 跨模块行为"即触发重三审，未量化判据，窄改动也进重审。
2. **执行面按全量**：R1(dsh-find-simplifications) → R2(dsh-code-review) → R3(dsh-archive-agent-notes) 三个代理，各自 SKILL 开头就要求读全仓 `AGENTS.md`/`packages/AGENTS.md`/`defensive-patterns`/`architecture`/Agent Notes 树，然后才 `change-scope` 拿 diff。三个"全量语义审"串行跑一个几行的 diff，耗时自然放大。
3. **轻审判据靠人判断**：契约已写"纯结构重构（零行为变更，测试+门禁可证）走轻审或简化路径"，但"是否真零行为变更"无机器化判据，靠主会话直觉。
4. **轮次/工具上限无默认值**：契约写"每个代理设轮次/工具调用上限"但没给数字。

> 反例实证：一次 3–5 行 diff 的修改，因"跨模块"命中触发，三个代理各按全仓语义审跑一遍，耗时与改动量严重不匹配。

## Decision

保留**有界并行、上限两路**（三路同时并行被否决——三路共享同一 diff 解读、R3 的 ADR 面与 R1/R2 代码面结论可能互扰；但两路并发是安全的，因为 R3 后置可等 R1/R2 收口再合并）。组合不固定（由主会话按工作量/负载决定），禁止三路同时并行。保留「行为保持第一证据 = 测试 + 门禁」既有立场。

### 1. 触发枚举显式化

"改行为/安全面/IPC 帧契约/发版链路/跨模块行为"从宽泛关键词改为**明确清单**，命中任一才重三审：

- 触碰 `src/**` 与 `tests/**` 之外的行为契约面（含 `.github/workflows/**` 的打包/发版链路、`resources/**` 的运行时捆绑、`templates/**`/`docs/**` 的契约口径）。
- 涉及 `async`/生命周期/事件序/取消/异常/并发（D001–D003、R1/R3 语义面或 defensive-pattern 类）。
- 改 IPC 帧契约（跨包/事件帧 ID、`AppJsonContext` 源生成契约）。
- 改发版链路（自更新、安装脚本、打包 workflow、签名/校验面）。
- 用户显式指定的批量事后审核。

**不在清单**（走轻审/简化）：纯换名/纯注释/纯测试断言调整/`dotnet format` 自动修/文档-only 且零行为契约变更。

### 2. 面收窄量化（审的范围，不审整仓）

每个审核代理在 `scripts/change-scope.sh` 产出 diff 基础上，**只读**：

- diff 触及的文件 + 它们**直接依赖/被依赖的相邻件**（一层以内）；
- 与本 diff 直接相关的契约/标准段落（如 `coding-standards` 行为契约节、`architecture-standards` 对应 R 条、相关 ADR 的 Consequences）。

**禁止**开局从头读全仓 `AGENTS.md`/`defensive-patterns`/`architecture.md`/Agent Notes 树；这些改为**按 diff 面按需引用**（需要哪条读哪条）。

### 3. 轻审判据机器化前置

"是否真零行为变更"由**主会话在进入步骤 5 前用脚本判据**决定，而非直觉：

- `change-scope.sh` 输出 diff，主会话据此判定是否含行为面（`async`/`await`/事件/`change` 面/`[]`/`Task.Delay`/`+`/`-` 语义改动、IPC 帧字段、新类型）。
- 命中"纯结构重构"（零行为变更 + `dotnet test` 绿 + 机械化门禁绿）→ **跳过重三审**，直接走轻审（R2 代码面即可，R1/R3 免）。
- 未命中才进完整重三审。

**"零行为变更"判据（缺了这条是本次教训来源——**判据不明确导致把"删除/改动进程 env 注入"误判为"零行为变更走轻审"。凡命中下述任一即**不是**零行为变更，须重三审）：

- 改动 `psi.Environment` / 进程环境变量注入（增删改传给子进程的 env）——本次教训：去掉 `pnpm_config_store_dir` env 属行为变更。
- 增删改**公共 API 签名/参数**（含 `record` 字段、`internal const` 常量、方法的 public/internal 参数表）——去掉 `CliShimSetup`/`BuildSetup`/`BuildShellExportBlocks` 的 pnpm 参数属行为变更。
- 增删改子进程的参数、工作目录、spawn 形态、插件安装流程。
- 删除/新增/变更**可观察副作用**（写文件、改 shell rc、改注册表、发 IPC 帧）。
- 触碰 `async`/`await`/`Task`/`CancellationToken`/`lock`/并发/生命周期（即使只删，也须确认无连带行为）。

**判据用法**：逐一对照上述，任一命中 → 重三审；全部未命中且测试/门禁绿 → 轻审。**宁可保守**：判据模棱两可时就重三审（轻审只省时间，漏审的代价是行为缺陷漏网）。

> **防逃逸机械前置**：上述判据是**缺省档**——FULL 档路径（组合根级/门禁判据改动/承诺三重审核的 proposed ADR/行为契约面）由 `scripts/verify-review-tier.py` 机械判定并强制重三审，执行者不得以「零行为变更」覆盖。机制见 [2026-09-03-review-tier-escape-proofing](2026-09-03-review-tier-escape-proofing.md)（implemented）。

### 4. 评审任务有界化（简报定界，一次完整跑完）

每个审核代理的任务由**主会话简报定界**——简报给出与 diff 规模相称的**范围 + 定向检查项 + 明确不做清单**，代理在该简报内穷尽检查后一次返回完整结论。量化参考（主会话按 diff 规模覆盖）：

- 单次 diff 视野 ≤ 200 行变更（超限分批简报，不单次吞全 diff）；
- 定向检查项 ≤ 5 条（多了代理无从聚焦）；
- 明确不做清单：明示该路**不必**做什么（如 R1 不必全仓找简化、R3 不必全量 supersession 扫描），把 skill 的通用默认收窄到本 diff 面。

**无「到限中断取部分结论」出口**——中断即未审计，中断后必须重新完整跑该路（铁律，见等待纪律）。上限的作用是**让简报有界从而一次跑完**，不是给代理设运行中断点。

#### 4.1 简报模板（机械校验，`scripts/verify-review-brief.py`）

每路评审主会话必须产出下述固定结构简报（供 `verify-review-brief.py` 校验——文件/字段/面收窄一致性）。**Scope 必须区分「需深审面」与「陪跑文件」**——机器门禁已盖的文件（dotnet test/format/md-links/adr-format 等绿）列陪跑，代理只扫读不精读；真正需逐行判读的才列深审面。这防止「17 文件 / 819 变更行」类规模数字诱导代理铺开精读全部：

```
# R<N> 评审简报（<路名>）

## Scope
- base: <git ref>  head: <git ref>（评审对象 = `git diff <base>..<head>`）
- 需深审面（精读，逐行判读）：<文件清单——真正承载本路语义判断的文件>
- 陪跑文件（机器门禁已盖，扫读确认即可）：<其余变更文件；无则写"无">
- diff 面相邻件（一层以内，按需引用）：<清单或"无">

## Directed checks（≤5 条）
- [ ] <检查项 1：要验证什么 + 证据位置>
- [ ] …

## Explicitly out of scope（明确不做）
- <该路不必做的收窄清单——把 skill 通用默认收窄到本 diff 面>
- …

## Report contract
- 返回 `Blocker[]`/`Suggestion[]`，每条 `文件:行 + 一句证据`；空即"无发现"
```

**字段规则**（脚本强制）：
- `Scope` 必须给出 `base:`/`head:`（脚本校验存在性；与 `change-scope.sh` 输出的一致性是主会话写简报时的责任，脚本不比对两工具输出）；**「需深审面」必须列出实际承载本路语义判断的文件，且不得为空**（脚本校验非空——`需深审面：无` 属违规）；「陪跑文件」可写"无"。
- `Directed checks` 必须 1–5 条、每条可证伪（含验证对象与证据位置），不得为空。
- `Explicitly out of scope` 必须至少 1 条（没有不做清单 = 简报未收窄，等同无界任务）。
- `Report contract` 固定（Blocker/Suggestion 契约）。
- 简报须在启动评审代理前写好并存为 `<repo>/.review-briefs/R<N>-<topic>.md`（gitignore），脚本读它校验。

#### 4.2 三路默认收窄（简报的「不做」基线，可按 diff 调整）

- **R1（dsh-find-simplifications）**：默认不做全仓简化候选扫描；只评估本 diff **新增/改动面**是否引入可简化的新构造（新增 internal 方法、重复、过度设计）。
- **R2（dsh-code-review）**：默认不追 diff 面之外的调用方全图；只验证 diff 触及的接口双侧（改动方法调用方 + 实现方）+ 留评审项（D001–D003/R1/R3/IPC）在本 diff 面的命中。
- **R3（dsh-archive-agent-notes）**：默认不全量 83 篇 supersession 审计；只核对本 diff 新增 ADR 的格式/口径/与**直接相关** note 的 supersession 关系 + 本 diff 若含归档动作才做对应审计。

> 本文档早期版本「到限未收口即中断，返回已有部分结论」与「中断即未审计」铁律冲突，已废除（2026-09-03）；`feature-flow.md` 步骤 5 已同步。

## Alternatives considered

- **三路同时并行（R1/R2/R3 无界并发）**：本可省时间，但三路共享同一 diff 解读、R3（ADR 面）结论可能因 R1/R2（代码面）修复而失效；并行会撞"跨路冲突需主会话合并"的复杂度。落败；禁止三路同时并行。
- **全串行（R1→R2→R3 依次）**：原方案，最稳但耗时最大，与改动量不成比例。被「有界并行、上限两路」取代——两路并发在"扩散成本"与"跨路合并复杂度"之间取平衡（R3 后置等 R1/R2 收口即可合并，不撞跨路失效）。
- **只改 trigger 不动执行面**：省事，但触发更精确了、执行仍全量，耗时改善有限。落败；触发 + 执行面一起收窄。
- **把 SKILL 全量上下文改成必读**：与"按需引用"相反，会继续放大耗时。落败；改为按 diff 面按需引用。
- **给每个代理固定 token 预算而非工具上限**：token 预算难精确映射"审多少面"，工具调用次数更直接对应"读了多少上下文"。落败；改为简报定界（范围 + 定向检查项 + 不做清单），一次完整跑完，不设中断点。

## Consequences

**收益**：触发从宽泛关键词收敛到明确清单，窄改动不再因"跨模块"误入重三审；执行面从全仓收窄到 diff 触及件 + 一层相邻；"纯结构重构"有了 `change-scope.sh` + 测试/门禁绿的机器化判据，命中即跳重审；评审任务由简报定界（范围 + 定向检查项 + 不做清单），一次完整跑完，无中断点（中断即未审计须重跑）。

**代价**：
- 面收窄可能漏审跨模块隐藏耦合。缓解：`change-scope.sh` 的 `changed` 表 + 主会话简报里的"风险点/定向检查项"仍要求主会话提示潜在耦合点；"行为第一证据 = 测试 + 门禁"兜底不变。
- 触发枚举可能漏 case。缓解：保留"用户显式指定"兜底 + 门禁（D004/D005/A 系）仍机器兜底结构面。
- 简报量化参考（视野 ≤200、检查项 ≤5）为经验默认，可能需调。缓解：主会话按 diff 规模调整简报宽度，不必动机制。

**Testing**：流程契约，机械校验用 `scripts/verify-review-brief.py`（简报模板/字段/面收窄，`--self-test` 6 夹具）与 `scripts/verify-review-tier.py`（档位判定，`--self-test` 10 夹具）；门禁验证用 `verify-adr-format.py`（校验本 ADR 通过）与 `verify-md-links.py`（校验 `feature-flow.md` 指向本 ADR 的相对链接可解析）。`feature-flow.md` 步骤 5 已同步改写为指向本 ADR 的触发枚举 + 面收窄 + 轻审判据 + 有界并行（上限两路、禁止三路同时并行）+ 简报定界（§4，启动评审前跑 `verify-review-brief.py --enforce`）。
