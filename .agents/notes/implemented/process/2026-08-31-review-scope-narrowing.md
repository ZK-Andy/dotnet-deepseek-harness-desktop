# Agent Note: review-scope-narrowing（三重审核按 diff 面收窄——触发枚举化 + 面收窄量化 + 轻审前置机器化）

Status: implemented

中文（双语暂不启用；启用时恢复 .md + .zh.md 配对 + .i18n.yaml）

## Problem

`feature-flow.md` 步骤 5（三重审核执行契约）当前**触发面宽、执行面全量、缺量化**，导致"窄范围修改"也背"全仓语义审"的成本，耗时与修改范围不成正比：

1. **触发条件写得宽**：凡"改行为/安全面 / IPC 帧契约 / 发版链路 / 跨模块行为"即触发重三审，未量化判据，窄改动也进重审。
2. **执行面按全量**：R1(dsh-find-simplifications) → R2(dsh-code-review) → R3(dsh-archive-agent-notes) 三个代理，各自 SKILL 开头就要求读全仓 `AGENTS.md`/`packages/AGENTS.md`/`defensive-patterns`/`architecture`/Agent Notes 树，然后才 `change-scope` 拿 diff。三个"全量语义审"串行跑一个几行的 diff，耗时自然放大。
3. **轻审判据靠人判断**：契约已写"纯结构重构（零行为变更，测试+门禁可证）走轻审或简化路径"，但"是否真零行为变更"无机器化判据，靠主会话直觉。
4. **轮次/工具上限无默认值**：契约写"每个代理设轮次/工具调用上限"但没给数字。

> 反例实证：一次 3–5 行 diff 的修改，因"跨模块"命中触发，三个代理各按全仓语义审跑一遍，耗时与改动量严重不匹配。

## Decision

保留**有界并行、上限两路**（三路同时并行被否决——三路共享同一 diff 解读、R3 的 ADR 面与 R1/R2 代码面结论可能互扰；但两路并发是安全的，因为 R3 后置可等 R1/R2 收口再合并）。组合不固定（由主会话按工作量/负载决定），禁止三路同时并行。保留「行为保持第一证据 = 测试 + 门禁」既有立场。

### 1. 触发枚举显式化

"改行为/安全面/IPC 帧契约/发版链路/跨模块行为"从宽泛关键词改为**明确清单**，命中任一才重三审：

- 触碰 `src/**` 与 `tests/**` 之外的行为契约面（含 `.github/workflows/**` 的打包/发版链路、`resources/**` 的运行时捆绑、`templates/**`/`docs/**` 的契约口径）。
- 涉及 `async`/生命周期/事件序/取消/异常/并发（D001–D003、R1/R3 语义面或 defensive-pattern 类）。
- 改 IPC 帧契约（跨包/事件帧 ID、`AppJsonContext` 源生成契约）。
- 改发版链路（自更新、安装脚本、打包 workflow、签名/校验面）。
- 用户显式指定的批量事后审核。

**不在清单**（走轻审/简化）：纯换名/纯注释/纯测试断言调整/`dotnet format` 自动修/文档-only 且零行为契约变更。

### 2. 面收窄量化（审的范围，不审整仓）

每个审核代理在 `scripts/change-scope.sh` 产出 diff 基础上，**只读**：

- diff 触及的文件 + 它们**直接依赖/被依赖的相邻件**（一层以内）；
- 与本 diff 直接相关的契约/标准段落（如 `coding-standards` 行为契约节、`architecture-standards` 对应 R 条、相关 ADR 的 Consequences）。

**禁止**开局从头读全仓 `AGENTS.md`/`defensive-patterns`/`architecture.md`/Agent Notes 树；这些改为**按 diff 面按需引用**（需要哪条读哪条）。

### 3. 轻审判据机器化前置

"是否真零行为变更"由**主会话在进入步骤 5 前用脚本判据**决定，而非直觉：

- `change-scope.sh` 输出 diff，主会话据此判定是否含行为面（`async`/`await`/事件/`change` 面/`[]`/`Task.Delay`/`+`/`-` 语义改动、IPC 帧字段、新类型）。
- 命中"纯结构重构"（零行为变更 + `dotnet test` 绿 + 机械化门禁绿）→ **跳过重三审**，直接走轻审（R2 代码面即可，R1/R3 免）。
- 未命中才进完整重三审。

### 4. 轮次/工具上限给默认值

每个审核代理设**默认上限**（可被主会话覆盖）：

- 工具调用 ≤ 12 次；
- 单次 diff 视野 ≤ 200 行变更（超限分批，不单次吞全 diff）；
- 轮次 ≤ 2（第 2 轮只做首轮 blocker 的确认/收口）。

到限未收口即中断，返回已有部分结论。

## Alternatives considered

- **三路同时并行（R1/R2/R3 无界并发）**：本可省时间，但三路共享同一 diff 解读、R3（ADR 面）结论可能因 R1/R2（代码面）修复而失效；并行会撞"跨路冲突需主会话合并"的复杂度。落败；禁止三路同时并行。
- **全串行（R1→R2→R3 依次）**：原方案，最稳但耗时最大，与改动量不成比例。被「有界并行、上限两路」取代——两路并发在"扩散成本"与"跨路合并复杂度"之间取平衡（R3 后置等 R1/R2 收口即可合并，不撞跨路失效）。
- **只改 trigger 不动执行面**：省事，但触发更精确了、执行仍全量，耗时改善有限。落败；触发 + 执行面一起收窄。
- **把 SKILL 全量上下文改成必读**：与"按需引用"相反，会继续放大耗时。落败；改为按 diff 面按需引用。
- **给每个代理固定 token 预算而非工具上限**：token 预算难精确映射"审多少面"，工具调用次数更直接对应"读了多少上下文"。落败；用工具调用/轮次上限。

## Consequences

**收益**：触发从宽泛关键词收敛到明确清单，窄改动不再因"跨模块"误入重三审；执行面从全仓收窄到 diff 触及件 + 一层相邻；"纯结构重构"有了 `change-scope.sh` + 测试/门禁绿的机器化判据，命中即跳重审；轮次/工具上限有了默认值（可覆盖），到限即返回，杜绝无限挂起。

**代价**：
- 面收窄可能漏审跨模块隐藏耦合。缓解：`change-scope.sh` 的 `changed` 表 + 主会话简报里的"风险点/定向检查项"仍要求主会话提示潜在耦合点；"行为第一证据 = 测试 + 门禁"兜底不变。
- 触发枚举可能漏 case。缓解：保留"用户显式指定"兜底 + 门禁（D004/D005/A 系）仍机器兜底结构面。
- 量化参考值（工具 ≤12、视野 ≤200、轮次 ≤2）为经验默认，可能需调。缓解：作为可覆盖默认值，首轮跑完按实际调整。

**Testing**：流程契约，不引入独立测试；门禁验证用 `verify-adr-format.py`（校验本 ADR 通过）与 `verify-md-links.py`（校验 `feature-flow.md` 指向本 ADR 的相对链接可解析）。`feature-flow.md` 步骤 5 已同步改写为指向本 ADR 的触发枚举 + 面收窄 + 轻审判据 + 有界并行（上限两路、禁止三路同时并行）。
