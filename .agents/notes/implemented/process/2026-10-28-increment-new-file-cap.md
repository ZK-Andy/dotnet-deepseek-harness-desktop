# Agent Note: 增量闸补新文件帽，封新文件免检通道

Status: implemented

Review: FULL/2026-10-28/R1=ok R2=ok R3=ok

## Problem

file-max（既有文件净增 ≤150）只计 BASE 时已存在的文件，新文件全长免计——豁免的历史理由是首轮强制时唯一的 OVER 是一个新写的 362 行 gate 脚本（整文件即净增、无可拆面，ADR `2026-10-14-increment-gate-enforce`）。但这条豁免后来成了自己的通道：把新代码塞进新文件就完全跳过尺寸计量，「多开文件」成了闸下的理性策略【推断 · 未证——机制由豁免构造直接可得，但它对近期批散射的实际贡献量未单独计量】；这正是文件粒度评审观察到的「小功能修改横跨多个文件」现象的激励面之一。

## Decision

新增第五帽 `newfile`（默认 400）：计量纯新增文件（`--diff-filter=A` numstat 的 added 行数；相似度 <50% 的改名按 delete+add 呈现，其加侧计入）与 worktree 时刻的未跟踪文件（整文件行数，与 gross 同一读取窗口）；既有文件 file-max（150）与 gross（600）不变。具名豁免标记扩一位：「增量闸豁免：gross ≤ N，fanout ≤ N[，packages ≤ N][，newfile ≤ N]」——一次性语义不变（ADR 落进基线即失效）；标记行须整体在本次新增行内（锚定 EXEMPT_RE 命中行，旧标记随批次失效的判据因此闭合到整行）。帽值 400 的标定：近 30 个非合并批（截至 2026-10-28）每批最大新文件 200 行（`X11FocusBootstrap.cs`，`7773d65`，n=30，手工源文件）；历史 n=100 窗口（2026-09-28..2026-10-12，ADR `coupling-increment-baseline`）单文件净增最大 360 行；窗口外的首轮强制批（2026-10-14，`af25eb1`）出现 362 行新写 gate 脚本——即当年触发新文件豁免的形态。生成物大批不走本帽的正常通道，与 gross 同走具名豁免（活先例：2026-10-22 架构图退役批 `gross ≤ 15000`；前闸时期的 `978d62c` 13.7k 行 HTML 为体量参照）。手工源文件的实测极值都在 400 之下。

## Alternatives considered

- **维持新文件免计**：落败——散射激励是本 ADR 的动因本身。
- **新文件与既有文件同帽 150**：落败——重演当年误报：整文件即净增、无可拆面的大新文件（历史实测 362 行）会被硬拦，当年正是为它开的豁免。
- **每批新文件数量帽（如 ≤3）**：落败——数量不对应害处：一个 900 行新文件在数量帽下合法，而散射的实际代价恰恰是单文件不可读、不可审；长度才是对应的量纲。
- **只靠 gross 600 兜新文件**：落败——gross 是批总量，多个中等新文件叠加时每个仍各免检，触顶的补救是拆批而不是收敛文件粒度。

## Consequences

- 新批的大新文件超 400 行即红：补救 = 拆文件，或走一次性具名豁免（标记写入本批 ADR，批次落地即失效，不会沉淀为长期放宽）。
- 「新代码塞新文件」的免检通道关闭；既有文件 150 帽语义不变。
- 帽值依据两个实测窗口的极值（362/200）；未来极值超帽走豁免通道，不默认放宽。

## Testing

- `--self-test`：numstat argv 三形态（全量/既有过滤/新增过滤）、`_sizes` 五元组、e2e（新增文件与改名加侧喂 newfile 不喂 file-max、worktree 时刻未跟踪文件计入且**承重**——夹具 450 行 > 暂存路径的 400，删掉合并分支断言即红）、`_check` 五帽六行、EXEMPT_RE 的 newfile 位（含 packages 缺省形态）全部 ok。
- pre-commit/pre-push/CI 走同一 `_measure`，无分叉面；本批自身为首次活体：两个新 ADR（28/29 行）在 400 帽下通过。
