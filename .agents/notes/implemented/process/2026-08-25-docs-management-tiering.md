# Agent Note: docs-management-tiering

Status: implemented

## Problem

文档与 ADR 全部以 Markdown 文件形态存于各处（项目内 `.agents/notes/` + 本地 `HANDOFF.md`/`.plan/`）。该模式经三门禁与生命周期纪律验证健康，但三类规模化管理压力已经出现：

1. **跨项目可见性缺失**——多个项目仓各有自己的 notes，跨仓查一条决策没有统一入口；
2. **会话层本地文档不受版本保护**——`HANDOFF.md`/`.plan/` 不入 git，2026-08-25 用户删除 `/mnt/work/码字工坊/` 当天就产生了位置表陈旧引用（活例）；
3. **生态空位确认**——GitHub 调研（2026-08-25，gh CLI 六步配方）：ADR 工具链、Spec 驱动开发、AI 记忆层三个流派各占一角，「跨仓聚合 + 生命周期治理 + agent 原生文件优先」的三合一工具不存在。

## Decision

**四层分离方向**（各层独立，按触发条件分步实施；停在第一层也是合法终态）：

1. **项目级 ADR 存储不动**——决策与代码同 PR 进出的原子性是根基（评审上下文、blame、门禁可达），一寸不让；
2. **框架级决策沉淀到独立治理仓**（先例：devops-template）——跨项目通用的方法论决策（命名规范、流程卡、门禁标准演进）入治理仓并自带门禁，各项目仓留实例与指针；
3. **会话记忆加版本保护**——HANDOFF/.plan 定期快照至私有仓（cron 级成本），解「未版本化会死」；
4. **工具增量只做只读聚合视图**——扫描多项目根的 notes/HANDOFF 产出统一索引页，永不回写源文件，无双写漂移问题。

**第 1 层已落地**（2026-08-27）：本仓 `HANDOFF.md` 完成**状态/叙事分层**——「交接更新记录」降为有界滚动窗口（保近期 2 个会话批次），越过窗口的叙事条目归档至 `.plan/journal/<YYYY-MM>-session-journal.md`（gitignore 纯本地）；durable 决策/取舍仍在 git 跟踪的 ADR/cookbook/README/AGENTS，本区不复述。由此明确了「每个事实只有一个家」在会话层的具体落点：**叙事轨迹 vs durable 决策分离**——归档 journal 只丢叙事，不丢决策。

**升级触发条件**（满足其一才投入对应层）：①跨项目查同一决策 ≥每周一次 → 第 4 层索引器；②某条框架决策在两个仓里出现分歧 → 第 2 层治理仓；③HANDOFF 因误删丢失过数据 → 第 3 层快照。

## Alternatives considered

- **整体搬入中心化工具/服务**：落败——制造第二个事实源必然漂移；agent 对外部系统有认证/API/网络摩擦而文件零依赖；生态实证无人成功把存储中心化（最火的工具全部建立在「文件在代码仓里」前提上）。
- **只删旧条目不复述**：落败——靠人自觉，无机器兜底，会话一忙即复发（HANDOFF 膨胀的原始成因）。
- **HANDOFF 保持全量但补预算**：落败——治标不治本，体积仍在增长。
- **HANDOFF 全进 git 跟踪**：落败——违背「本地工作文档不提交」既有决定，且 ADR 已是决策家。
- **引入 basic-memory**（3.8k⭐，本地 Markdown 为源的理念与我们同构）：落败——需要常驻 MCP 服务端做索引与关联，放弃「文件零依赖」优势换一层服务依赖；其生命周期治理能力并不强于现有三门禁 + archive 审计。
- **引入 github/spec-kit**（131k⭐，spec 驱动开发官方工具包）：落败——它管「写代码前的规格流程」（spec→plan→tasks），不管「决策档案的存档与跨仓检索」，相邻问题不同痛点；其分层思想值得日后借鉴进 feature-flow 卡（另行小改，不引依赖）。
- **引入 log4brains / adr-tools**：落败——前者 2024-12 起停更且单仓假设、生成物面向人类浏览器；后者 2024-04 起停更；两者的编号模板模型与本仓 lifecycle class 封闭集 + 状态即目录约定不自洽。

## Consequences

- 收益：方向与生态证据已固化，未来触发条件命中时无需重新调研辩论；第 1 层（HANDOFF 分层 + journal 归档）已落地，HANDOFF 从 271 行/7494 词收敛到 156 行/3633 词，且滚动窗机制让体积不再单调递增。
- 代价/风险：proposed 期间项目级 ADR 继续增长，拖得越久第 2 层治理仓的潜在迁移成本越高（缓解：触发条件已显式化，不会无声恶化）；第 3 层快照落地前 HANDOFF/.plan 保持裸奔状态（当前知情接受）。journal 归档后，跨会话检索早期叙事需查 `.plan/journal/`（gitignore，不入 git，丢失只丢叙事）。
- 生态快照存档（2026-08-25 星数）：architecture-decision-record org 方法论库 16.7k；adr-tools 5.6k（2024-04 停更）；madr 2.4k（活跃）；log4brains 1.6k（2024-12 停更）；github/spec-kit 131k；mem0 64k；graphiti 30k；basic-memory 3.8k。
