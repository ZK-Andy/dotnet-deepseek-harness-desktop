# Agent Note: 回环代理日志降噪——逐请求/逐隧道 trace 默认关，异常面恒打

Status: implemented

Review: FULL/2026-10-06/R1=ok R2=ok R3=ok

## Problem

`<home>/logs/host.log` 磁盘面已有界（`HostLog.MaxBytes` 5 MB 单文件 + 一代 `.old`，ADR [shell-observability-diagnostics](2026-08-24-shell-observability-diagnostics.md)），但**信噪比**失衡。实机 2026-10-06 快照（全文 30521 行）：

- `代理请求` 7975 行 + `代理流转` 7909 行 + `代理回包` 66 行 = **15950 行（52.3%）**：每次页请求落一行请求行 + 一行终态行（终态中 2xx 成功 7518、非 2xx 457）；
- `代理升级隧道已建` 661 行 + `代理升级隧道已收` 639 行 = **1300 行（4.3%）**：页面 mux 重连 churn 的逐事件轨迹。

两类合计 17250 行（**56.5%**）。最近一次会话（末 343 行）里 315 行是这两类（92%），其中非 2xx 仅 10 行。真正承载诊断的异常面（`代理未铸币即调用：502` 90 行、`代理中继异常收尾` 72 行、`代理升级无路由：502` 5 行、`代理升级上游响应` 81 行）被流水淹没——读一次故障要先翻过上万行「200 OK」。

## Decision

**成功路径的逐请求/逐隧道 trace 默认不落盘，异常面一条不少；需要全量流水时用配置开关打开。**

- **降噪面（默认静默）**：
  - `代理请求`——仅 `Trace` 打开时落（默认档连失败/慢请求也不落请求行：终态行自带方法/路径）。
  - `代理回包` / `代理流转`——仅「上游状态 ≥ 400」或「耗时 ≥ 慢阈值」或 `Trace` 打开时落。
  - `代理升级隧道已建`——仅 `Trace` 打开时落。`代理升级隧道已收`——`Trace` 档恒落，默认档只在**故障收场**（先结束的泵任务以异常收场）时落：实机 639 条收行里恰 1 条此形态（2026-09-27 首读即断的 mux 排障现场，其前一行 `已建`、其间无 `上游响应`），砍掉该例外即让这类故障默认零留痕。正常 EOF 收场与取消收场（`Task.Exception` 为 null）不落；先结束的是正常 EOF 侧、另一侧随后才故障的情形不在本行（由 `Task.WhenAll` 的 catch 静默，属继承语义）。判据抽 `DshLoopbackTunnel.ShouldLogTunnelClose`，三态理论钉住。
- **恒打面（不动，且本批补齐一处漏痕）**：代理拒畸形请求 502、代理未铸币即调用 502、代理中继异常收尾、代理跟进终止 502、代理遇外链 Location 即停、代理回包超限 502、**代理回包体不可读 502（本批补：此前页收 502 却零留痕）**、代理升级无路由/路由非法/上游不可达 502、上游零字节即关、代理升级上游响应、代理服务 holder 页、代理指南越界即拦 403、`代理记忆端口 … 已被占`（前缀可 grep）。
- **收尾统计**：`Dispose` 落一行 `[shell] 代理统计：N 请求（M 成功 / K 失败），升级隧道 T`（N=0 且 T=0 时不打；幂等守卫防重复）。口径：`N` = 受理面进入转发的请求——含**未铸币 502**（未到 dsh）与**壳自造 502**（体不可读/回包超限）两类失败，本地 holder/指南面与畸形请求不计；`失败` = 上游状态 ≥400 或壳自造 502，`成功` = `N - 失败`；`T` = 升级请求受理数（含未到 dsh 的升级 502——计数点在路由校验之前；独立成列）——逐隧道 trace 静默后，它是「本会话有 mux 流量」的唯一证据。
- **配置模型**：新节 `ProxyLogging` → `ProxyLogging` record：`Trace`（bool，默认 `false`）、`SlowRequestMilliseconds`（int，默认 `2000`；不可表示为 Int32、小数或 < 1 一律回默认）。装载 fail-safe 覆盖缺文件/坏 JSON/节或键缺失/类型不符/值不可用/文件不可读。**慢判据 = 到终态就绪的等待**（不含响应体与流时长）——长活 SSE 按该口径永不判慢，其异常面照旧恒打。
- **无人值守面**：`DSH_DESKTOP_PROXY_TRACE=1` 显式打开逐请求 trace（先例 `DSH_DESKTOP_PREINSTALL_AUTO`），由 `smoke_unattended_env` 在三平台冒烟腿导出。存活门 `smoke_client_alive`（`scripts/lib/smoke-verdict-lib.sh`）以逐请求行与隧道建行为判据、且是落定门的唯一行为支——产品默认静默后，腿内必须由该面回到既有判据。

## Alternatives considered

- **分离文件 `logs/proxy.log`**：host.log 干净且逐请求证据全留。落败原因：诊断 zip 的白名单按条目枚举（`DiagnosticsExporter`），新文件要同步白名单与「事实单一家」，而收益与开关重叠——需要流水时打开 `Trace` 即可。
- **多代滚动 / 按日分卷 / gzip 旧代**：落败原因：owning ADR 明写「轮转只保一代」是先前批次的有意取舍；本批降噪后 10 MB 上限的留存时长从数天拉到数周，扩代数的磁盘收益被吃掉，却要改一个已定的策略。
- **引入日志框架分级（Serilog/NLog/MEL）**：落败原因：owning ADR 已判过——双写 + 轮转约 40 行即够，引框架违背轻壳定位。
- **均匀采样（每 N 条留一条）**：落败原因：证据面变随机，排障不能保证拿到需要的那条；计数 + 异常面恒打是确定性语义。
- **只砍终态行、保留请求行**：落败原因：一次请求仍至少一行，会话级仍是数百行；且无终态状态的请求行信息量最低。
- **让冒烟腿改判据（数新标记）而非打开 trace**：落败原因：把「产品默认该多吵」与「CI 需要多少证据」重新绑在一起，且要同时改三条腿的脚本与夹具；打开 trace 让腿内回到既有判据，产品默认面不受影响。
- **产品保留「前 3 条成功行」以保存活门**：落败原因：把 CI 的阈值（≥3）与内容类型判据（只有 json/SSE 终态行匹配）烙进产品日志策略；产品侧无从表达「哪 3 条算法定证据」。
- **把 env 当常规配置通道**：落败原因：生产档位仍以 appsettings 为单源；env 只作无人值守腿的显式打开面（该面既有 `DSH_DESKTOP_PREINSTALL_AUTO` 先例），不承接常规可调参数。

## Consequences

- **买到的**：默认 host.log 基本等于「异常清单 + 状态迁移 + 每会话一行统计」。同一快照口径下 17250 行流水默认消失（−56.5%）；单会话 315 行流水 → 仅剩 10 行非 2xx 终态 + 1 行统计。
- **付出的**：成功路径默认不再逐条留痕——「某次请求是否到达 dsh」这类时序排障需先打开 `Trace`（或无人值守 env）复现；`代理请求` 行的头/体/cookie 细节只在 `Trace` 档可见，隧道 `先关方` 细节默认档只在故障收场时可见（正常收场需 `Trace`）。
- **观测语义变化**：旧判据「host.log 里有 200 行 = 有请求在跑」作废，改由统计行承担；统计是会话级而非请求级证据。
- **留档（本批不做）**：`ProxyLogging` 的装载面与 `RuntimeTimeouts`/`UpdateOptions` 逐句同形，可抽通用节装卸器（净删约 40 行）；同批应把后两者的 `JsonElement.GetInt32()` 换成 `TryGetInt32`——越界/小数会抛 `FormatException`，而它们的 `Load` 只 catch `JsonException`、又在启动早期调用，会把配置损坏升级成启动异常。两项同属配置装载面，留作独立批以免在日志批里改基线关键文件。

## Testing

- 成功路径默认静默：GET/POST 各一例断言无逐请求行（原两处断言随本批翻转）。
- 异常面恒打：上游 401 一例断言 `代理回包：401` 在场。
- 慢请求恒打：阈值 10 ms + 桩在目标路径注入 80 ms 延迟（真实耗时比较，非退化阈值）。
- `Trace` 开关：请求行与终态行同时在场。
- 统计行：1 成功与 1 失败（401）两例断言完整行（含隧道列）；零请求不打；升级隧道计 1（mux-only 会话）。
- 装载面：默认值、缺节、全键覆盖、类型不符、小数/越界/负值/字符串回默认、根非对象（`[]`/`"x"`/`42`/`null`）回默认、坏 JSON 抛 `JsonException`、`Load` 对坏 JSON/缺文件/不可读文件 fail-safe。
- 无人值守面：`ApplyTraceEnv` 纯缝三态（仅字面 `"1"` 打开，`"0"`/null/其他值一律维持文件档位）。
- 隧道收行判据：`ShouldLogTunnelClose` 三态理论——完成收场不落、取消收场不落、故障收场落、`Trace` 档恒落。
- 失败计数与读序：每请求至多一次失败（壳自造 502 分支 `if (!failed)`），`Dispose` 先读 `failed` 再读 `request` 保证 `成功 = N − 失败 ≥ 0`。两处壳自造 502 分支本身无夹具（回包超限需 32 MB 体，代价大于回归价值），靠检视核对。
